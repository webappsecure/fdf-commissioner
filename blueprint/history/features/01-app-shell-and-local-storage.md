# Feature: App shell and local storage

**From build-plan:** feature 1
**Build attempt:** 1
**Branch:** feature/app-shell-and-local-storage
**Status:** verified

## Goal

Replace the Expo starter with the real app foundation: a responsive navigation
shell with light and dark themes, a durable local SQLite database that works on
iOS, Android, and web, and a static, installable, offline-capable PWA build.
Later features add leagues and rules on top of this without reworking it.

## In scope

- **Database layer.** `expo-sqlite`, opened once per app run through a
  client-only provider. A tiny migration runner keyed on `PRAGMA user_version`
  with one baseline migration creating `app_meta(key TEXT PRIMARY KEY, value TEXT NOT NULL)`.
  A `launch_count` row, incremented once per app start, proves data survives
  restarts. No league tables yet (feature 3).
- **Shell.** Replace the starter tabs with two destinations: **Leagues** (`/`,
  empty state "No leagues yet", no actions yet) and **Settings** (`/settings`,
  showing storage status and launch count). Bottom tabs on phone and tablet
  native, the existing top-bar tab layout on web. Content is centered with a
  maximum width, uses few elements per screen, and does not need scrolling at
  these sizes.
- **Theme.** Color tokens live in `src/constants/theme.ts`, are neutral and
  utilitarian, and leave room for a team-color accent later. A user preference
  chooses **System** (follow the device, the default), **Light** (always light),
  or **Dark** (always dark). It is set on Settings with a three-option selector,
  stored in `app_meta` as `theme_preference`, applied at startup before first
  paint where possible, and takes effect immediately without a restart.
- **Remove the starter demo.** Delete the Expo welcome content and the files
  that only it uses (animated icon and splash overlay, hint row, web badge, the
  explore screen, collapsible). Keep the themed text and view helpers, the
  `use-color-scheme` hooks, and the external link helper only if still used.
- **Web storage persistence.** On web, request `navigator.storage.persist()` at
  startup and show the result (persistent, not granted, or unsupported) on
  Settings.
- **Static PWA.** Change `web.output` from `server` to `static`. Add a web app
  manifest (name "FDF Commissioner", standalone display, theme and background
  colors, icons from existing assets) and a small service worker that caches
  same-origin GET responses so the installed app opens offline after first load.
  Web build must run with no server.
- **Typecheck passes.** The final tree has zero `tsc --noEmit` errors.

## Out of scope

- Leagues, teams, players, or any rules tables (features 2 to 6).
- Export and import (feature 19).
- Dice, rules engine, test runner setup (feature 2; `/tests` adds the runner).
- Localization, push notifications, per-league or per-team themes.
- GitHub Pages deployment and README install docs (feature 20). This feature
  only guarantees the static export works and is installable.
- App store assets or EAS builds.

## Data / contracts

- Database file name: `fdf-commissioner.db`.
- `PRAGMA user_version` is the schema version; migrations are an ordered array and
  each runs once in a transaction. A failed migration leaves the database at the
  prior version and shows an error state.
- `app_meta(key TEXT PRIMARY KEY, value TEXT NOT NULL)`. Known key:
  `launch_count` (decimal string), written once per app start, never per render.
  `theme_preference` (`system`, `light`, or `dark`); a missing or unrecognized
  value is treated as `system`.
- Routes: `/` (Leagues) and `/settings`. Later features add routes under
  `/league/[id]`, as listed in the project overview.
- Storage status values shown on Settings: `persistent`, `not granted`,
  `unsupported`, and `native` on iOS and Android.

## Notes for the AI

- Baseline observed at spec time: `npx tsc --noEmit` reports three errors. Two are
  missing generated types (`expo-env.d.ts` absent, so `*.css` and `@/global.css`
  fail). The third is in `src/components/app-tabs.web.tsx`, a starter file this
  feature replaces. No Verify command exists yet.
- `app.json` currently has `web.output: "server"`, `experiments.reactCompiler`, and
  typed routes. Keep the compiler and typed routes.
- Static rendering runs in Node, so never touch `expo-sqlite`, `navigator`, or
  `window` at module scope or during render on the server.
- Follow `blueprint/context/coding-standards.md`: functional components, kebab-case
  file names, no `any`, minimal comments, no em dashes in any text.
- Do not add dependencies beyond `expo-sqlite`. React Native's `Appearance` API
  can be used to follow the system setting, and `app.json` `userInterfaceStyle`
  is already `automatic`, so a forced scheme is applied in JS, not in native config.
- On web, avoid a flash of the wrong theme at startup where practical, but a
  brief flash before the stored preference loads is acceptable.
- Do not run commit, push, or merge. Do not deploy.
